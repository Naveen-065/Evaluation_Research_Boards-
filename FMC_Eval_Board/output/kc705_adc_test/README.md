# KC705 DAC81416 + ADS5282 shunt-measurement image

This directory contains a conservative, fixed-function DAC/ADC test for the
CaravelReRAM-SenseEval card on KC705 J2. It is separate from `baseline/` and
does not alter the proven passive-first image or any FMC I/O voltage setting.

## Hardware interlock

The bitstream always starts with both VIO outputs at zero: `probe_out0` is the
ADC enable and `probe_out1` is the DAC enable. In this state:

- J2 D8 / `FPGA_MCLKIN_P` is low (ADC sample clock stopped).
- J2 D9 / `FPGA_MCLKIN_N` is actively low.
- `FPGA_nADCRST` is low, holding the ADS5282 in hardware reset.
- `FPGA_nCS` is high; `FPGA_SCK` and `FPGA_SDATA` are low.
- `ADC_PD` is low and every unrelated daughtercard output retains the reviewed
  static state. In particular, `FPGA_LOE` remains low.
- `AQ1_nRST` is low, holding the DAC81416 in reset; `AQ1_nCS` and `AQ1_nLDAC`
  are high; `AQ1_SCK` and `AQ1_MOSI` are low.

The KC705 J2 signals are in HR Bank 12 at measured VADJ = 1.8 V. The ADS5282
return pairs use input-only `LVDS_25` with `DIFF_TERM FALSE`. **The PCB has no
receiver termination footprints on these seven pairs. Fit a 100-ohm
receiver-end termination across each of OUT1, OUT2, OUT3, OUT4, OUT5, LCLK and
ADCLK before powering the connected card.** ADC hardware reset initializes
registers; it is not a verified guarantee that the LVDS outputs are high
impedance. With ADC_PD held low, stopped clocks and zero VIO enables alone
do not establish the electrical behavior of unterminated LVDS outputs.

## DAC shunt-rail profile

`enable_dac_shunts.tcl` requires the literal acknowledgement
`PCB_CONNECTED_RAILS_CHECKED DAC_REFERENCE_NETWORK_CHECKED`. It applies a
1-us hardware reset pulse, waits the datasheet-required 1 ms, enables the
internal 2.5 V reference and gives it another 1 ms, sets all 16 DAC ranges to
0..5 V, loads only the three required channel codes, and powers up only those
three channels:

| DAC | Series resistor | Load-side rail | Code | DAC-side target |
| ---: | --- | --- | --- | ---: |
| 0 | R9, 470 ohm | `VCC_READ` | `199A` | 0.5 V |
| 2 | R10, 470 ohm | `VCC_SET` | `199A` | 0.5 V |
| 5 | R11, 470 ohm | `VCC_RESET` | `8000` | 2.5 V |

The final `DACPWDWN` value is `FFDA`: DAC0, DAC2 and DAC5 are active; every
other DAC channel remains powered down and clamped to ground through the
DAC81416's internal 10-kohm path. Measure all three board rails before enabling
the ADC. `disable_dac_shunts.tcl` reasserts DAC hardware reset and refuses to
run while the ADC is active.

R9, R10 and R11 are each 470 ohms between the DAC-side setpoint and the named
load-side rail. The direct shunt-current relation is `I = (AINx_P - AINx_N) /
470 ohms`; the ADC code also includes the conditioning-amplifier gain and must
be calibrated before reporting absolute current. With the downstream load
absent, expect almost no shunt drop, so the ADC will mainly show its zero
offset/noise rather than a useful load current.

The released DAC schematic has a hardware reference-network error that cannot
be repaired in FPGA logic: U1 pin 33 `REF` is marked no-connect, while TI calls
for at least 150 nF from REF to REFGND when using the internal reference; C6
places 100 nF from pin 34 `REFCMP` to ground, where TI specifies 330 pF typical.
Before using `enable_dac_shunts.tcl`, fit at least 150 nF from U1 pin 33 to
REFGND and replace/verify C6 as 330 pF. Then measure REF at approximately 2.5 V
before trusting any DAC output.

## ADC behavior after deliberate enable

`enable_adc_test.tcl` requires the literal command-line acknowledgement
`TERMINATIONS_INSTALLED`. It then sets the one-bit fixed-purpose VIO enable.
With the sample clock still stopped, the logic applies an explicit reset
high-low-high sequence (the low pulse is 1 us), waits 1 ms after release, and
sends these seven 24-bit SPI words at 2 MHz. It then waits another 10 ms, starts
the 10 MHz sample clock, and waits 100 us before declaring ready:

| Address | Data | Purpose |
| --- | --- | --- |
| `03` | `0002` | required initialization |
| `01` | `0010` | required initialization |
| `E3` | `0060` | low-rate PLL setting for 10 MSPS |
| `C7` | `8001` | required initialization |
| `DE` | `01C0` | required initialization |
| `42` | `8001` | differential input-clock selection |
| `25` | `0000` | normal ADC data; all digital test patterns disabled |

Each frame is address A7..A0 followed by data D15..D0, MSB first. SDATA is
stable before each rising SCLK edge. The serial clock period is 500 ns, below
the requested 5 MHz maximum.

The 10 MHz signal is generated by a 200 MHz to 10 MHz PLLE2, then forwarded
through an ODDR onto D8. D9 remains a driven-low reference, matching the PCB's
single-ended AC-coupled input-clock network.

## Capture

LCLK reaches the OUT1..OUT5 and ADCLK IDDR clock pins through BUFIO. A matching
BUFR in BYPASS mode clocks the shift registers and ILA, keeping the receive
path in the source-synchronous I/O region. Six LCLK cycles shift 12 bits per
data lane. The ILA probes are:

| Probe | Width | Contents |
| --- | ---: | --- |
| `probe0` | 60 | completed raw `{OUT5, OUT4, OUT3, OUT2, OUT1}` 12-bit groups |
| `probe1` | 60 | live raw shift registers in the same order |
| `probe2` | 12 | `{ADCLK rise, ADCLK fall, OUT[5:1] rise, OUT[5:1] fall}` |
| `probe3` | 32 | ADC/DAC controller status; bit 0 is ADC run and bit 14 is DAC enable |
| `probe4` | 4 | `{ADCLK frame lock, 0..5 DDR-pair counter}` |

The capture logic detects a returned ADCLK rising transition and uses it to
reset the six-pair phase. Probe 4 shows when that frame lock has occurred. This
is still diagnostic capture rather than final channel deskew. The shifter
appends the IDDR rise bit followed by the fall bit; because ADS5282 transmits
LSB first, the displayed 12-bit group is bit-reversed relative to the usual
numeric ADC word. Use the known rail conditions and raw ADCLK samples to
confirm edge order and any remaining rotation before adding a production bit
reorder. The three shunt
sense pairs are routed to ADS5282 analog channels 1, 2 and 3 respectively;
their serial results are OUT1, OUT2 and OUT3 in the capture.
Only OUT1..OUT5 reach J2; OUT6..OUT8 remain local to daughtercard J8.

## Build and use

Run these commands from this directory on the Windows PC with Vivado in PATH:

```powershell
vivado -mode batch -source build_adc_test.tcl
vivado -mode batch -source program_adc_test.tcl
vivado -mode batch -source check_adc_safe.tcl
```

The build produces `build/kc705_adc_test.bit` and
`build/kc705_adc_test.ltx`. `program_adc_test.tcl` only accepts the previously
verified cable `localhost:3121/xilinx_tcf/Xilinx/00001f14c98801` and leaves
both VIO enable bits at zero. `check_adc_safe.tcl` independently verifies DONE,
EOS and the live named VIO probes: run=0, ADC clock stopped, hardware reset
asserted, configuration incomplete, nCS high and SCLK low.

For an inspection that does not write either enable, run
`vivado -mode batch -source inspect_fmc_readiness.tcl`. It prints the live
controller state and sampled configuration-mode bits. A controller-state
pass does not verify the physical supply voltages or PCB rework. The last
inspection on 2026-10-19 passed the disabled-state checks but reported mode
bits `000`; check SW13 and set JTAG mode `101` while powered off before the
next connected power-up.

Never insert or remove the FMC card while either board is powered. After
powering off, set KC705 configuration switch SW13 to JTAG mode so an unrelated
BPI-flash image cannot start first: position 3 (M2) ON, position 4 (M1) OFF,
and position 5 (M0) ON, giving M[2:0] = 101. With power still off, check the
three rails for shorts, correct/verify the DAC reference network described
above, fit the terminations, and seat the card. Power on, reprogram this image
(the KC705 SRAM configuration is lost whenever it is powered off), then
measure VADJ = 1.8 V before enabling the DAC:

```powershell
vivado -mode batch -source enable_dac_shunts.tcl -tclargs PCB_CONNECTED_RAILS_CHECKED DAC_REFERENCE_NETWORK_CHECKED
```

Verify approximately 0.5 V on `VCC_READ`, 0.5 V on `VCC_SET`, and 2.5 V on
`VCC_RESET`. After fitting/verifying all seven 100-ohm terminations, enable the
ADC and capture normal analog data:

```powershell
vivado -mode batch -source enable_adc_test.tcl -tclargs TERMINATIONS_INSTALLED
vivado -mode batch -source capture_adc_shunts.tcl
```

`capture_adc_shunts.tcl` writes a timestamped CSV under `captures/`. Stop the ADC
clock and reassert hardware reset at any time with:

```powershell
vivado -mode batch -source disable_adc_test.tcl
vivado -mode batch -source disable_dac_shunts.tcl
```

For the pure-RTL reset/SPI sequence test, install Icarus Verilog and run:

```powershell
.\run_sim.ps1
```

The scripts are prepared for remote execution but do not themselves start an
SSH session, change VADJ, program Si5351, or program any device other than the
single detected `xc7k325t` on the exact known JTAG cable.
